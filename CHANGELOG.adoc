= Changelog

This file lists notable changes to cl-adoc.

The cl-adoc library and SPEC.adoc use separate versions. SPEC.adoc defines
the AsciiDoc subset that cl-adoc parses and renders.

== Unreleased

=== Fixed

A bracketed line such as `[aside]` or `[1.2.0]` was read as a block attribute
line. Attribute lines are not nodes, so its text was dropped from the
document. It also ended the paragraph it appeared in.

Now only `source`, `stem`, and `pass` make an attribute line. Any other
bracketed line is ordinary text.

=== Language

A recognized attribute line must be followed by a block it applies to.
Otherwise, parsing signals `syntax-error` at the attribute line.

Before this change, the attribute was silently ignored. For example,
`[source,lisp]` above a paragraph and `[pass]` above a `----` block both had
no effect.

Documents that relied on that behavior now fail to parse. The error names the
line to fix.

SPEC.adoc records both rules in the Blocks section.


=== Documentation

Rewrote project documentation, comments, docstrings, and fixture prose for
clearer technical English.

No parser behavior changed.

No public Lisp interface changed.

SPEC.adoc still describes language subset v2.

== 0.2.0

=== Language

Added description lists.

A description item has this form:

----
term:: definition
----

The delimiter is the first `::` followed by one of these:

* a space
* the end of the line

This rule keeps `image::path[alt]` as a block image macro. In a macro, the
target starts immediately after the colons. In a description item, a space or
the end of the line follows the colons.

The same rule lets a term contain colons. For example, `` `:date:`:: `` is
read as the term `` `:date:` ``.

A definition can continue on later lines, like a list item.

A term can also appear with no definition on the same line. In that case, the
definition starts on the following lines.

Description lists were added because a consumer needed them. The anchor
specification uses description lists throughout. anchor is also meant to render
its own specification. Before this release, it could not do that.

=== Interface

Added these node types:

* `description-list`
* `description-item`

Added these accessors:

* `description-item-term`
* `description-item-definition`

`node-children` walks both the term and the definition.

A term can contain inline nodes, such as links and code spans. A definition can
contain them too.

=== Known limits

A prose line that contains `::` followed by a space starts a description item.
There is no escape for this case yet.

This limit is recorded in SPEC.adoc.

== 0.1.0

First release.

=== Language

Added the first language subset.

This release supports:

* document headers with a title
* `:key: value` document attributes
* section headings through four levels
* generated section IDs
* paragraphs
* bold text
* italic text
* monospace text
* backslash escapes for inline formatting delimiters
* unordered lists
* ordered lists
* checklist items
* link macros
* image macros
* inline image macros
* block image macros
* autolinks for bare `http://` and `https://` URLs
* admonitions
* blockquotes
* listing blocks
* source blocks with a language
* inline mathematics
* mathematics blocks
* passthrough blocks

Bold, italic, and monospace spans use constrained delimiter rules. These rules
leave names such as `snake_case_name` unchanged. They also leave arithmetic such
as `2 * 3 * 4` unchanged.

SPEC.adoc defines the full subset. It also lists excluded features and explains
why they are excluded.

About a dozen SPEC.adoc entries are still marked as planned.

=== Interface

Added `parse-string` and `parse-file`. Each function returns a document.

Added `render-html`. It renders a document as HTML.

Added these tree-walk functions:

* `map-nodes`
* `collect-nodes`
* `find-node`

Added these query functions:

* `node-text`
* `heading-id`
* `document-headings`
* `document-uses-stem-p`
* `document-references`
* `reference-target`

These functions answer the questions that a build usually needs to ask about a
document.

Rendering dispatches on a backend object. A second output format can therefore
be added as a set of methods. It does not require changes to the existing HTML
renderer.

=== Known limits

Attribute lists end at the first `]`. There is no way to escape `]` inside an
attribute list. This also limits what inline `stem:[...]` can contain.

A bare `++++` block is mathematics in cl-adoc. Asciidoctor treats the same block
as passthrough. Use `[pass]` to request passthrough in cl-adoc.

Code spans are literal in cl-adoc. Asciidoctor applies formatting inside code
spans.

Each limit is recorded in SPEC.adoc with its reason.
